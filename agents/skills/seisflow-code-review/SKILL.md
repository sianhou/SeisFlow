# SeisFlow 编码原则审核

先阅读 `../seisflow-code/SKILL.md`，以其中的原则和用户当前任务要求为依据。

## 审核范围

- 优先审核用户指定范围；没有指定时，审核本次任务的 diff，并阅读理解改动所必需的调用位置。
- 区分本次新增的问题和原有代码，不要求对整个工区进行清理。
- 用户明确要求的检查、异常处理或接口调整，不作为违背默认原则的问题。

## 审核内容

- 可读性：命名是否表达含义，流程是否直接，抽象是否有实际用途，是否出现不必要的嵌套或技巧。
- 功能范围：是否新增未要求的边界检查、防御分支、兜底、重试、兼容层或其他功能；区分正常业务分支和额外校验。
- 改动范围：是否修改无关文件、批量格式化或改变无关接口、配置、依赖；是否有可避免的连带改动。
- 函数文档：新增或修改的函数是否明确说明功能、参数及返回内容，文档是否与实现一致。

## 审核结果

- 对实际发现的问题给出文件与行号、违反的具体原则，以及最小修改建议。
- 不为了凑问题提出假设性的边界风险，也不建议添加默认原则禁止的防御代码。
- 编码任务的交付前自审：直接修正本次范围内的问题，再检查修改后的 diff。
- 用户单独要求审核：报告问题，不自动修改代码，除非用户同时要求修复。
- 没有发现问题时明确说明审核通过；如果未运行验证，或存在无法核实的内容，如实说明。原则审核通过不等于功能测试通过。
