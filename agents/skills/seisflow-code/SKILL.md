# SeisFlow 编码原则

## 可读性优先

- 使用表达含义的变量、函数和类名，保持控制流程直接、清楚。
- 避免压缩写法、过深嵌套和难以理解的技巧；抽象应减少实际重复并明确职责，不为未来可能的需求设计框架。
- 沿用附近代码的命名、格式和文档风格。

## 不添加边界检查或额外功能

- 按任务约定的正常输入实现功能，不新增参数合法性、类型、形状、范围、空值或文件存在性等边界检查。
- 不新增防御性分支、兜底值、异常吞掉、自动重试、兼容层或其他未要求的功能。
- 正常业务逻辑所需的条件分支可以保留；不要将正常业务分支扩大为额外输入校验。
- 保留已有检查和行为，不为贯彻本原则批量删除旧代码。用户明确要求新增校验或处理特定异常时，以用户要求为准。

## 最小改动

- 只修改完成任务必需的文件和代码，优先复用现有实现。
- 不顺带整理无关代码、批量格式化、调整依赖或改变配置。
- 除任务明确要求外，保持现有公开接口、调用方式、返回值和保存格式兼容。
- 不覆盖用户已有的无关改动。

## 函数说明

- 新增函数和方法必须有 docstring；修改函数时，为所改函数补全或更新说明，包括构造函数。
- 明确说明函数完成什么，以及每个参数的含义；实例方法的 `self` 和类方法的 `cls` 无需解释。
- 对有返回值的函数说明返回内容；涉及 Tensor 时，写明调用者需要知道的形状或维度含义。
- 对 `*args`、`**kwargs` 说明用途或转交对象，不用含糊的“其他参数”代替。
- 文档与实现一致，不为补文档扩大到未修改的函数。

## 完成前

- 检查本次 diff，确认未引入额外功能或无关修改。
- 按改动影响进行必要验证，不为简单、可逆改动添加重复实现逻辑的测试。
- 使用同目录下的 `../seisflow-code-review/SKILL.md` 审核本次改动，修正范围内的问题后再交付。
