# 研究月志：2026-08

## 2026-08-28

### 研究进展

- 完成 i64 patch halo PSNR 诊断：对 `shot_0107` 的414个64×64预测 patch，分别裁掉四周 `0、2、4、8、16` 像素，比较 EMA/No-EMA 和1、2、4次独立采样平均的结果。
- PSNR 按数据定义范围 `[-1,1]` 使用 `data_range=2`，即 `PSNR = 10 log10(4/MSE)`。
- halo=16 的逐 patch PSNR 算术平均提高 `1.891～2.552 dB`，但中位增益只有 `0.231～0.293 dB`；全部像素 pooled PSNR 变化仅 `-0.066～+0.064 dB`。
- 真值能量最高25%的104个困难 patch 在所有权重、采样数和 halo 组合下均退化，代表性 patch 也显示大幅正增益主要来自中心为空或很安静的区域。
- 更新 hwgpu/mac 的数据构建脚本：按 `301×1501` 炮尺寸将 i64/i128/i256 overlap 分别设为32/101/242，预计每炮生成414/416/450个 patch，使不同尺寸的样本数接近。
- 相关方向：[Halo 中心裁剪](directions_halo.md)（暂停）；[Patch Size 与有效上下文](directions_patch_size.md)（继续研究）。

### 重要信息

- 当前证据不足以支持继续把 halo 作为主要改进方案；暂不优先实现 i64 中心裁剪后的完整铺炮推理。
- Halo 已拆分为独立研究方向并标记为暂停；仅在 bands3 完整验证集或 i128 中心区域出现新的稳定边缘收益时重新考虑。
- halo 诊断只比较同一个64×64 patch 内的不同裁剪区域，没有增加模型输入上下文，因此不能据此判定增大 patch size 无效。
- Patch Size 方向继续保留为下一步重点，但后续改为直接比较 i64 输入64与 i128 输入128保留中心64的受控筛选实验；若困难 patch 没有稳定收益，则停止继续扩大 patch，不进入 i256。
- 样本数匹配依赖很高的 overlap，只增加相关的平移裁剪；i128/i256 每炮 patch 数据量约为 i64 的4倍/17倍，不能把样本数相同理解为独立信息量或计算成本相同。

### 下一步计划

1. 明确 i64 与 i128 的共同中心64评测网格、训练预算和停止条件，避免把 patch size、overlap 和独立采样集成混在一起。
2. 使用 i128/overlap101 重建并核对每炮416块、炮级划分和数据体积，再完成 smoke test。
3. 先运行短程 i128 筛选；只有困难炮和高能量 patch 出现稳定改善后，才进入完整训练与 halo/overlap 推理对照。

## 2026-08-31

### 研究进展

- 完成纯 patch-level `AugmentedDiT2DModel`：复用 PixelDiT 的 `AugmentedDiTBlock`、2D RoPE、RMSNorm、QK Norm 和 gated FFN，移除 pixel-level `PiTBlock` 分支，新增带条件 AdaLN 的 patch 输出层并 fold 回二维图像。

- 完成独立训练与采样入口 `AugmentedDiTSeisDimReconNeRF.py`，并增加 i64、NeRF bands0、T/P4 的 hwgpu 训练和整炮重建脚本。
- 新增10项 AugmentedDiT 定向测试，覆盖矩形输入、条件通道拼接、REPA 特征、`max_period` 行为与持久化、builder 参数传递、RoPE 维度约束，以及训练参数和 train/sample 分发；连同相关 PixelDiT/DiT 回归测试共25项通过。
- 相关方向：[AugmentedDiT 架构对照](directions_augmented_dit.md)（下一步重点）。

### 重要信息

- 当前只完成实现、测试和实验入口，尚无训练结果，不能判断 AugmentedDiT 是否优于传统 DiT。
- AugmentedDiT-T/P4 与 DiT-T/P4 的宽度、深度、head 数和 token 数一致，但按当前3通道输入估算参数量分别约为21.83M和23.58M；同时 `max_period=10` 与 Diffusers DiT 的默认时间编码不同，后续结论需明确是端到端架构比较还是严格 block 消融。

### 下一步计划

1. 运行 AugmentedDiT-T/P4 i64 bands0 训练和每100 epoch重建，对齐 DiT-T/P4 的数据、batch、epoch、EMA、upcast attention 和评测流程。
2. 比较验证集 PSNR、MSE、收敛曲线、显存、吞吐和 GPU-hours，并记录实际 checkpoint 与结果目录。
